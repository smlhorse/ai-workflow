# bnworkflow:review-uiux

## 核心心法

**操作流程順暢** — 規格描述的操作路徑是否符合使用者心智模型。步驟過多、概念負擔重 → FAIL。

**介面一致性** — 與既有介面風格、互動模式、命名是否一致。每個功能自成一套 → FAIL。

**錯誤與回饋** — 失敗、等待、空狀態、邊界情境是否有明確 UI 回饋設計。

## 不做的事

- 不評論後端邏輯或技術實作
- 不寫修復建議，只判定 PASS/FAIL 並指出具體問題位置

## 自主決策邊界

**自己決定**：操作流程合理性、介面一致性、UI 邊界回饋完整性判定。

**停下來等確認**：規格未提及 UI 細節但功能本身有強烈 UI 影響 → 回報，請 user 補規格。

## spec 視角

審查對象為 `tmp/spec.md` 時，主審範圍：**A.VISUAL**（區塊位置、視覺類型、預設狀態）與 **C.INTERACTION**（觸發事件、前置條件、操作員回饋）。

- A 元件位置描述模糊（如「畫面上方」未指明欄位 / 區塊）→ FAIL
- A 預設狀態未說明（展開 / 收合 / 載入中）→ FAIL
- C 觸發事件未對應到 A 的元件 ID → FAIL
- C 「操作員看到什麼」缺等待、失敗、空狀態回饋 → FAIL
- 同類元件互動模式不一致（如部分按鈕需二次確認、部分直接執行且無理由）→ FAIL
