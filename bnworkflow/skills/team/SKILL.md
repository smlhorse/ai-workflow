# bnworkflow:team

## 用法

```
/bnworkflow:team join {代號}     ← 指派身分報到
/bnworkflow:team handoff         ← 把當前工作現況寫回自己的工作管理檔
/bnworkflow:team who [代號]      ← 查組織表：誰負責什麼、主管是誰、現在在哪
```

家在 `.team/`（不進版控）：`org.md` 組織表（含代號對照與預設主管）、`members/{代號}.md` 自我介紹卡、`handoff/{代號}.md` 工作管理檔、`.sessions.log` 掛勾寫的開關機流水（機器用，人不看）。三種檔案的版型與代號表住本 skill `templates/`，init 與本 skill 共用同一份。

**join 必做三件事**：讀自己的自我介紹卡與工作管理檔（載入人設與現況）→ 把本 session 名稱與 id 更新進組織表 → 把工作管理檔檔頭的「最後 session 名稱／最後 session id」蓋成本 session（**不動「更新時間」**，那是實際寫入現況時才更新的欄位）。第三件事沒做，session 結束時掛勾認不出這份檔是誰的，「未收尾」的安全網就不會啟動。

**handoff 完成後**狀態填「交接待接手」；session 仍要繼續做則填「進行中」。

## 核心心法

**工作管理檔是給下一棒動手用的，不是日誌** — 驗收標準只有一條：接手的人只讀這一份就能直接做下一件事，不必回頭問人。覆寫不追加，欄位依 `templates/handoff.md`，沒內容寫「無」不刪欄。長到一頁看不完＝沒整理。

**未驗過的不寫進「做到哪」** — 呼應「能用才叫完成」。沒驗的放「下一步」，否則下一棒以為完成了不再驗，錯誤穿透。

**踩過的坑一定要寫** — 這是這份檔存在的價值：坑沒寫下來，下一棒會再踩一次，成本比重做還高。

**身分不自封** — 沒被指派就不扮演成員、不寫任何 `.team/` 檔案，也不動組織表上別人的欄位。人設只影響表達（語氣／結構／提問風格），不改變工作規範與把關標準；review / verify 的判準不因人設鬆動。

**有名字才叫得到** — 跨 session 靠 session 名稱定址（`ListAgents` 查得到誰在線、`SendMessage` 送訊息，限同一台機器）。報到時取本 session 名稱登記；沒有名稱就請 user `/rename {代號}`（或下次以 `claude --name {代號}` 啟動），否則別人只知道你在、無法直接叫到你。

**在線與否以實際查詢為準** — 組織表的 session 欄只是上次登記，可能過期。要送訊息前先查一次真的在不在，不對已消失的 session 喊話；環境不支援跨 session 訊息時就以組織表為準，由 user 轉達。

**主管上任要讓部屬知道** — 主管在新 session 報到時，主動通知在線部屬改回報到這裡；通知不到的，部屬下次報到自己會從組織表讀到。

**待確認照原文搬** — 交接時「卡在哪等誰」逐字帶過去，不順手替 user 決定（No-Drift）。

**收工前先落檔** — context 快滿、要 `/clear`、anchor 說要交接、或一個主題告一段落，先寫回工作管理檔再收。掛勾只能在 session 結束時標「未收尾」並留下逐字稿路徑當補救，補救比不上當下寫。

## 不做的事

- 不把工作管理檔當歷史累積；要歷史看逐字稿與 git log
- 不在自我介紹卡重寫職能與判斷依據（住 `.claude/roles.md`，單一來源）
- 不寫密碼與個資進 `.team/`（不進版控不等於安全）

## 自主決策邊界

**自己決定**：工作管理檔的內容取捨與排版、離線判定、要通知哪些部屬。

**停下來問**：身分指派（誰扮演誰由 user 說）、自我介紹卡姓名與特質的初次設定、組織表的主管關係變更。
