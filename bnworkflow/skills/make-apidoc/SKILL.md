# bnworkflow:make-apidoc

## 核心心法

**SDD 內部合約 ≠ 對外開發者文件** — SDD 的 API 合約是給實作看的內部設計；對第三方串接者要的是「怎麼呼叫、認證、錯誤怎麼處理、範例」的開發者視角文件。

**指向 SDD、不重抄** — 欄位/錯誤碼權威在 SDD；本文件做對外呈現，不複製會漂移的副本。

## 涵蓋面向（按需，不全要）

- **端點清單**：path、method、用途
- **認證授權**：如何取得與帶入憑證
- **請求/回應**：參數、範例、錯誤碼與處理
- **整合指南**：串接流程、速率限制、版本策略、範例程式

## 觸發判斷

- 有對第三方/外部開放的 API → 走
- 純內部 API（無外部消費者）→ 略過
- 判斷不出 → 停下問

## 路徑

預設 `docs/api/<service>/api.md`（可搭配 OpenAPI 規格檔）；專案 CLAUDE.md 可覆寫路徑/格式。

## 不做的事

- 不複製 SDD 內容 → 欄位/錯誤碼指向 SDD，避免雙份漂移
- 不只寫成功回應 → 錯誤碼、限流、失敗處理都要對外說明
- 不憑空編端點 → 每個端點對應實際實作與 SDD 合約，無對應列待確認
- 不洩漏內部細節（內部 IP/endpoint/實作備註）進對外文件

## 自主決策邊界

**自己決定**：文件結構、範例撰寫、OpenAPI 產生方式。

**停下來問**：對外揭露範圍不明（哪些端點可公開）、版本/棄用策略未定、認證機制未定。

## 角色

程式架構師或資深 SA 主寫，資深工程師（SD）審規範一致性。review 掛 `review-program` + `review-sa`。設計完成後產出，交棒 `bnworkflow:make-code`。
