# 專案管理（操作總覽）

長週期、多功能、會不斷改來改去的專案，最怕變成「一堆 issue 混一桶、大小不分、管不動」。本檔說明怎麼運作才不會爛。

強制規則在 `.claude/CLAUDE.md`「變更分流與 Sprint 防波堤」；目錄地圖見根 `CLAUDE.md`「目錄結構」；本檔是可讀的操作總覽。

## 一句話定調

> **Sprint 是防波堤——開跑後 scope 凍結。冒出來的東西照三堆分流，只有「當前功能自己的細節」當下做，其餘一律不插斷、進池；換關口才 triage。backlog 大是正常的，它是「選菜的池」，不是「要清空的債」。**

## 三堆：每個冒出來的東西去哪

判準只有一刀要你記：**動到「已定案的規格/範圍」了嗎？** 動到＝你拍板；沒動＝AI 自理。（第二刀「現在做/延後」是 AI 的排程職責，不煩你。）

| 堆 | 是什麼 | 去哪 | 誰決定 |
|---|---|---|---|
| 🟢 沒動範圍的小改 | 改字、重構、修剛寫的錯、當場能修的小 bug | 直接 commit，只留 git log，**不進任何清單** | AI（digest 告知） |
| 🔵 動到範圍 | 改已定案規格／新增功能／決定不做 | `decisions.md`＋改 `specs/wbs`，**一律等你點頭** | 你 |
| 🟡 現在不做的 | 待修 bug／待做改善／待答問題 | `backlog/` 各一檔，**做完即刪** | 你定序（AI 提議） |

**三條讓它永遠不亂：**
1. 改字級 → 只 commit、不建檔（🟢吸收掉雜項的絕大多數）。
2. 進 sprint 的門檻＝**功能級**（多一項使用者能力）；改幾個字進不來。
3. backlog 做完即刪、sprint 完成即封存 → 活動清單永遠只有「未完成」。

## Sprint 三步循環

1. **規劃**：從 `backlog/`＋`wbs/` 挑「功能級＋這期值得做」的進 sprint。**用挑的，不是清空**。backlog 只標三態：`本期候選 / 之後 / 可能砍`。
2. **執行**：scope 凍結。冒出來的照三堆分流，🔵🟡不插斷當期，只有 blocker 例外。
3. **收尾**：封存本期 → 開下期前把 backlog 攤開 triage 一次（過時的直接砍，`decisions.md` 記一行）。

## 雙流程：你怎麼溝通 ↔ AI 怎麼執行

**你的溝通流程（很輕）**：自然講就好，不用分類、不用想「這進哪個檔」；一次講幾件都行；你唯一要做的決定＝AI 給 digest 時對🔵🟡點頭或否決。

**AI 的執行流程**：接收 → 兩刀分三堆 → 🟢直接做、🔵🟡扣住 → 主題告一段落給一張 digest → 你拍板 → 落檔排期。

**digest 範例**（一個主題告一段落就給）：
```
本輪冒出 3 項：
🟢 已做   [某處文字/樣式微調] (commit ….)
🔵 待拍板 [某功能想加的新能力] → 新功能，要進 WBS 排 sprint 嗎？
🟡 已入池 [已完成功能偶發的錯] → 建議進 bugs.md，blocker 或排下期？
```
你只回一句「X 排下期、Y 是 blocker 現在修」——AI 才動 WBS／立即修。**凡動到範圍的永遠等你這一句，改字級的不煩你。**
