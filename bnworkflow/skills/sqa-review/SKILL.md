# bnworkflow:sqa-review

**角色視角**：資深工程師（SD）— 程式 clean code、程式碼架構制定、程式層安全與效能。

## 核對邏輯

**Step 1–Anchor 驗收**：讀 `tmp/anchor.md`，拆成獨立需求清單，逐條對照 diff：
- ✓ diff 有明確對應
- ⚠ 有做但不完整
- ✗ diff 找不到對應

diff 中未對應任何需求的修改全部列 ⚠（改動溢出邊界）。

**Step 2–規格核對**：對本次 diff 每一個業務決策，確認來源真實存在於規格文件：

| 判定 | 條件 |
|---|---|
| ✓ | 規格文件有明確依據 |
| ✗ | 規格說 A，實作做了 B |
| 🔴 自行填充 | 規格未定義，AI 自行決定 → 需人工裁決 |

**Step 3–代碼掃描**：
- hardcode 帳密／金鑰／URL：grep 掃描所有被修改的檔案
- [FROZEN] 介面：是否被動過
- 測試腳本：若被修改，說明原因；無對應規格變更依據 → 列 ⚠

## 輸出

```
## Review：PASS / FAIL

🔴 自行填充（需人工裁決）：
- {檔案:行號} {說明}

✗ 不符規格：
- {規格說 A，實作做了 B}

⚠ 溢出邊界：
- {diff 中未對應需求的修改}

代碼掃描：
- hardcode：PASS／FAIL（{位置}）
- [FROZEN] 介面：未觸碰／有觸碰（{說明}）
- 測試腳本：未被修改／有被修改（{說明}）
```
